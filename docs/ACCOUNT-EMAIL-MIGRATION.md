# XDstar 邮箱验证迁移（2026-11-01，本地完成，未部署）

## 行为与边界

新注册先填写用户名、昵称、邮箱及密码，邮件链接验证成功才创建用户；不会在验证前建立可登录账号。注册、申请找回和邮箱占用均返回通用提示；请仅确认本人发起的注册操作。登录继续使用同一账号密码，可填写用户名、六位 UID 或已验证邮箱。

旧用户无需重新注册、设置密码或验证邮箱即可继续登录。升级不修改旧用户记录、内部 ID、UID、密码哈希、会话、密保、项目关联或存档；房间仍用原内部 ID 关联所有权。旧邮箱字段未经验证不具有登录/恢复权限。登录后自愿绑定邮箱，验证前保留原邮箱及原密保；验证成功后启用新邮箱、停用密保找回，撤销旧恢复请求与会话，重新用原密码登录。旧密保哈希保留，不用于已验证邮箱账号的恢复。改密码/邮箱或密码重置均使此前邮件令牌失效。

## SMTP 配置

仅在服务端环境或根目录 `.env` 设置，示例见 `deploy/accounts.env.example`：

| 参数 | 含义 |
| --- | --- |
| `XDSTAR_SMTP_HOST` | SMTP 主机名 |
| `XDSTAR_SMTP_PORT` | 默认 587；隐式 TLS 通常为 465 |
| `XDSTAR_SMTP_SECURE` | 465 使用 `true`；587 使用 `false`，强制 STARTTLS |
| `XDSTAR_SMTP_USER` | SMTP 登录名 |
| `XDSTAR_SMTP_PASSWORD` | SMTP 密码或邮箱提供方的授权码 |
| `XDSTAR_SMTP_FROM` | 单个发件邮箱地址，需要 SMTP 服务器授权 |
| `XDSTAR_ACCOUNT_ORIGIN` | 现有账号站点的完整 HTTPS Origin，用于生成固定来源链接 |

继续保留现有 `XDSTAR_ACCOUNT_SECRET`、数据库路径、Cookie 与代理配置。不能更换会话密钥来配合迁移；否则旧 Cookie 将无法验证。未配置 SMTP 时原账号登录、密保恢复正常，邮件操作返回通用提示，后台记录无敏感内容的 `email_delivery_failed` 事件；新注册无法完成。`admin warnings` 可查看发送失败事件，不输出 SMTP 错误、收件地址或令牌。

只增加 Nodemailer，不使用商业邮件服务、Redis、CAPTCHA 或新认证框架。TLS 使用系统证书验证，不提供跳过证书验证选项。实际收件还需管理员确认发件域 SPF/DKIM/DMARC 及 SMTP 提供方限制。

## 令牌和限流

令牌由 `randomBytes(32)` 生成，SHA-256 摘要存于 SQLite，30 分钟有效；用途、用户、认证版本与目标邮箱绑定，在事务中复检和一次性消费。邮件链接将令牌置于 fragment，浏览器加载后移除地址中的 fragment；GET 不消费，需用户显式提交 POST，保留 Origin、CSRF、no-store、no-referrer。重置后不自动登录，撤销全部会话，发送密码变更通知；换绑成功通知旧邮箱。

所有邮件用途共享每 IP 每小时 10 次、每收件地址每小时 3 次，以及适用的每账号每小时 3 次限制；找回额外按输入标识每小时 3 次。跨别名关联的私有限额静默抑制发送，避免通过 429 关联账号与邮箱；IP/输入标识限额返回 429。复用 SQLite 的 HMAC subject 与滚动窗口，进程重启不清空额度。SMTP 发送脱离公开响应，最多16个待处理任务；SMTP 有连接/握手/传输超时。发送失败删除对应令牌。后台发送队列不持久化，不自动重试，进程异常退出前未发出的邮件需用户稍后重新申请；已发送链接在重启后仍可验证。

第一阶段支持普通 ASCII 本地名称和 IDN 域名；保留输入的本地名称拼写，域名转 punycode 并小写，邮箱登录/唯一性比较整体忽略 ASCII 大小写，不移除点号或 `+` 标签，不支持带引号/国际化本地名称。唯一索引只覆盖已验证邮箱。

## 备份、升级与回退方案

此轮未操作正式服务器或正式数据库。未来经明确授权上线时：

1. 安排账号写入维护窗口，保留原镜像/源码、账号密钥及独立房间数据备份。在启动新版前运行 `npm --prefix accounts run admin -- backup <新的备份绝对路径>`。该命令直接以只读方式打开原库，使用 SQLite Online Backup API，**不会先迁移数据库**，也不会覆盖已有备份。不要在运行中只复制 `.sqlite` 主文件而忽略 WAL。备份含密码哈希及个人信息，限制权限并加密离机保存。
2. 在隔离副本上使用 SQLite 检查 `PRAGMA integrity_check`、`PRAGMA foreign_key_check`，核对用户数、原 ID/UID/密码哈希/会话/密保/项目和存档。另核对房间 `ownerUid`、数量与原内部 ID 对应；不要按昵称重建关联。若现有库已有重复的已验证邮箱，先停止上线并人工核实；迁移会失败回滚，不删除、覆盖或合并用户。
3. 在副本启动新版，自动事务迁移 v2 → v3，只新增邮件令牌表及索引、迁移记录；v1 经现有 v2 迁移后升级。确认旧账号密码登录和原 Cookie 仍有效，旧密保可找回、原房间可管理和存档可读；再验证新注册、绑定、换绑和重置，核对升级前后旧用户字段逐项相同。不要将新版库交给旧程序：旧程序会拒绝高版本。
4. 正式切换前另存最终一致性快照；只切换账号服务及账号前端，不改房间/ASR/实时通信服务。迁移后无需强制旧用户操作；由用户逐步自愿绑定。
5. 首选保留 v3 数据库修复程序。若必须回退旧程序，停止账号写入，先备份当前 v3 库，再恢复配套的升级前 v2 快照及原镜像/密钥；不要直接降低 `user_version`。这会丢失快照后的注册/密码/邮箱修改，需要预先核对维护窗口内增量并向受影响用户说明。不要恢复或重建房间所有权文件来配合账号升级。

## 验收范围

自动测试使用内存邮件收件箱、真实隔离 SQLite/Argon2id/Fastify Cookie/CSRF，验证注册、用户名/UID/邮箱登录、链接过期/重放/并发消费、用途隔离、重置、换绑、旧密保停用、SMTP失败、限流、重启与迁移。迁移测试使用固定的旧版 v2 建库模块在临时磁盘创建数据库，比较旧用户、UID、密码哈希、会话与关联数据并读取备份；房间集成测试单独覆盖真实网关所有权与跨设备管理。

真实 SMTP、收件可达性/垃圾箱、生产跨子域 Cookie、真实麦克风/豆包及物理手机另验；模拟成功不能替代这些验收。

实现参考：[Nodemailer SMTP](https://nodemailer.com/smtp/)、[OWASP 密码找回](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)、[OWASP 邮箱验证](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html)。

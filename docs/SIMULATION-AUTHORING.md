# 模拟字幕素材编写指南

这份文档写给**不写程序的人**。你不需要懂 Vue、TypeScript，也不用改任何代码，只需要会编辑一个文本文件，就能给实时字幕添加新的角色和台词。

看完这份文档，你可以：

- 修改现有的角色名字、台词；
- 添加新的角色、新的台词；
- 新建一个自己的素材包（比如「日常对话」「某部动画的台词」）。

> 本文只讲「素材」，不讲「程序」。程序如何运行、如何调度，属于开发者的事，你不用关心。

---

## 一、素材文件放在哪里

所有素材都放在项目根目录的 `materials/` 文件夹里，每个文件就是一个「素材包」。

```
materials/
  example.json   ← 现在网页使用的素材包
```

- 文件格式是 **JSON**，用**任意文本编辑器**都能打开编辑（Windows 记事本、VS Code、Notepad++ 都可以）。
- 现在网页只读取第一个素材包（按文件名排序），所以**想改网页上的内容，直接编辑 `example.json`**。
- 以后可以再放第二个、第三个素材包（例如 `daily.json`、`mygo.json`），用于在网页上切换或随机抽取；这个切换功能目前还没做。

## 三、素材包由哪几部分组成

一个素材包有五个部分（其中 `timing` 可以省略）：

| 部分 | 含义 | 是否必填 |
| --- | --- | --- |
| `name` | 素材包名称，只是给人看的标签 | 必填 |
| `timing` | 自动时间轴的语速与句间停顿 | 可省略 |
| `characters` | 角色列表（名字、编号、颜色） | 必填 |
| `lines` | 台词池（哪句台词属于哪个角色） | 必填 |
| `scenarios` | 七种测试场景各自要说的台词 | 必填 |

### 3.1 characters：角色列表

```json
"characters": [
  { "id": "a", "name": "我", "color": "#e8b088" },
  { "id": "b", "name": "小明", "color": "#91bcb2" }
]
```

- `id`：这个角色的**唯一编号**，用字母或数字都行（`a`、`b`、`person1`……），但不能重复。台词里要靠它找到对应角色。
- `name`：显示在字幕卡片上的名字。
- `color`：角色卡片用的颜色（可选，省略就用默认色）。写 `#` 加 6 位十六进制，例如 `#e8b088`。

**注意顺序**：网页最多同时显示 8 个人。`characters` 里第 1 个角色（`id` 为第一个的那个）代表**你自己**——你进房时输入的名字会替换掉它；第 2～8 个是自动加入的其他成员。

### 3.2 lines：台词池

```json
"lines": [
  { "character": "a", "text": "大家好。" },
  { "character": "b", "text": "今天天气不错。" }
]
```

- `character`：这句台词是**哪个角色**说的，填 `characters` 里已有的 `id`。
- `text`：台词内容。
- `at`、`duration`：这句台词的**开始时间**和**说话时长**（单位毫秒），都可以省略。省略时程序自动安排；填了就在「素材对话（时间轴）」场景里精确生效。详见第五节。

`lines` 里**台词和角色是绑定在一起的**，不是两张互不相干的表。这样以后加入影视、动画台词时，能保留「这句是谁说的」。

### 3.3 scenarios：七种测试场景的台词

网页上有七个模拟测试按钮，每个按钮要说什么，由 `scenarios` 决定：

| 场景键 | 用途 | 需要填什么 |
| --- | --- | --- |
| `rapid` | 单人连续快速讲话 | 3 句台词（数组） |
| `eight` | 8 人同时讲话 | 一个对象，里面是 `followUp`（每人追加的一句话） |
| `long` | 长句测试 | 1 句长台词 |
| `fade` | 渐隐时加入新句 | 2 句台词（数组） |
| `overflow` | 卡片内容溢出 | 1 句台词（会反复出现 20 次） |
| `interim` | 实时识别到确认 | 2 句台词（数组） |
| `stress` | 1 分钟压力测试 | 6 段，每段 8 句台词 |

说明：

- `eight`（8 人同时讲话）的 8 句台词，**取自上面的 `lines` 台词池**，按顺序分给第 1～8 位成员；`scenarios.eight.followUp` 只是每人额外追加的那一句话。
- `stress`（压力测试）必须正好是 **6 段，每段 8 句**，共 48 句。程序会按固定节奏让 8 个人轮流说，保证每次运行结果一致。
- 另外还有一个「**素材对话（时间轴）**」场景，它播放的是上面的 `lines` 台词池（不写在 `scenarios` 里），可以自动排时间，也可以由你在 `lines` 里手动指定时间。详见第五节。

## 四、怎么改

### 改一个角色的名字

打开 `materials/example.json`，找到对应角色，改 `name` 后面的字：

```json
{ "id": "b", "name": "丰川祥子", "color": "#91bcb2" }
```

改成：

```json
{ "id": "b", "name": "新名字", "color": "#91bcb2" }
```

### 加一个角色

在 `characters` 的方括号里，模仿已有的一行，加一行新的。**`id` 不能和已有的重复**：

```json
{ "id": "i", "name": "新角色", "color": "#123456" }
```

（注意：超过 8 个角色，网页现在也只会显示前 8 个。）

### 为角色加一句台词

在 `lines` 里加一行，`character` 填已有角色的 `id`：

```json
{ "character": "i", "text": "这是新角色说的话。" }
```

### 改某句台词

直接改 `text` 后面的字即可。

### 删掉一句台词或一个角色

- 删台词：删掉 `lines` 里对应的一整行（注意行末的逗号）。
- 删角色：删掉 `characters` 里对应的一整行；同时也要删掉 `lines` 里所有 `character` 指向它的台词，否则会报「找不到角色」。

### 改某个测试场景的台词

在 `scenarios` 里找到对应场景，改里面的字即可。例如改「长句测试」：

```json
"long": "改成你想让长句测试说的话。"
```

## 五、时间轴：自动和手动两种方式

「时间轴」决定每句台词**什么时候开始说、说多久**。素材包里有两类场景：

- **七个固定测试场景**（rapid / eight / long / fade / overflow / interim / stress）各有自己固定的节奏，你只管写台词，不用管时间。
- **「素材对话（时间轴）」场景**播放 `lines` 台词池，它有两种时间轴：**自动**（默认）和**手动**。

### 5.1 自动时间轴（默认，什么都不用填）

只要不写 `at` 和 `duration`，程序就按「语速」和「句间停顿」自动安排：

- 每句说多久 = 字数 × 语速（默认每字 30 毫秒）；太短保底 600 毫秒，太长封顶 1600 毫秒。
- 下一句开始时间 = 上一句结束 + 停顿（默认 500 毫秒）。
- 也就是**一句接一句地说，不会重叠**。

语速和停顿可以在素材包顶部的 `timing` 里改（都可不写，写了就覆盖默认值）：

```json
"timing": { "speechRateMs": 30, "gapMs": 500 }
```

- `speechRateMs`：每个字多少毫秒（数字越大，说得越慢）。
- `gapMs`：两句之间的停顿毫秒数。

例如下面这段（不写任何时间）：

```json
"lines": [
  { "character": "a", "text": "你好" },
  { "character": "b", "text": "大家好" }
]
```

自动结果是：第一句从 0 毫秒开始、说 600 毫秒；停顿 500 毫秒后，第二句从 1100 毫秒开始、说 600 毫秒。

### 5.2 手动时间轴（可选，精确控制、可重叠）

在 `lines` 的某条台词上写 `at` 和/或 `duration`，就按你写的来（单位都是毫秒）：

- `at`：这句从第几毫秒开始说。省略就按自动规则接着上一句排。
- `duration`：这句说多少毫秒。省略就按字数自动算。

两个字段可以只填一个，也可以都填。例如：

```json
"lines": [
  { "character": "a", "text": "我先说。", "at": 0, "duration": 1500 },
  { "character": "b", "text": "我插一句。", "at": 500, "duration": 1000 },
  { "character": "a", "text": "我接着说。", "at": 2000 }
]
```

效果是：

- 第 0 毫秒：角色 a 开始说「我先说。」，说 1500 毫秒（到 1500 毫秒结束）。
- 第 500 毫秒：角色 b 插话「我插一句。」，说 1000 毫秒——**和 a 重叠了**（因为 500 < 1500）。
- 第 2000 毫秒：角色 a 说「我接着说。」，时长自动按字数算。

想表达「几个人抢着说」，就让它们的 `at` 互相靠近或重叠；想表达「一问一答」，就把 `at` 依次错开。

> 手动填的 `at`、`duration` 只在「素材对话（时间轴）」场景里生效，不影响其他七个固定测试场景。

## 六、填错了怎么办

JSON 对「逗号、引号、方括号、花括号」很严格。最常见的错误是：

1. **少写或多写一个逗号**（逗号只用在两样东西之间，最后一样东西后面不能有逗号）。
2. **引号没配对**（每个字符串都要用英文双引号 `"` 包起来）。
3. **方括号/花括号没配对**（`[` 配 `]`，`{` 配 `}`）。
4. **忘了改逗号**：删掉一行后，上一行末尾还留着逗号。

**怎么判断和修复**：

- 如果整个文件格式坏了（括号/逗号/引号不对），网页会加载失败，并在房间里显示一条错误提示，内容大致是「素材包校验失败：……」，里面会说明是哪一块出了问题。
- 如果是逻辑错误（比如台词引用了不存在的角色 `id`），提示会告诉你「`lines[0].character` 必须指向 characters 中已存在的角色 id」。
- 建议用 **VS Code** 或 **Notepad++** 编辑：它们会给括号上色、报错，比记事本容易发现漏掉的括号和逗号。

**原则**：改之前先复制一份留底；改完立刻刷新网页看效果；一次只改一处，出错了好排查。

## 七、改完后怎么看效果

1. 保存文件。
2. 回到网页，刷新页面（F5）。
3. 输入名字进入房间，在「输入」里选「模拟字幕」，选一个场景，点「运行」。

- 想看你改的**角色名**：进房后会自动加入第 2～8 位成员，名字来自 `characters`。
- 想看你改的**八人台词**：选「8 人同时讲话」。
- 想看你改的**压力测试台词**：选「8 人对话 · 1 分钟压力测试」。
- 想看你改的**台词时间轴**（自动或手动）：选「素材对话（时间轴）」。

> 如果改的是 `materials/example.json`，刷新即可看到；如果新建了一个素材包，需要先重启 `npm run dev` 让程序发现新文件（这一步通常由开发者来做）。

## 八、哪些是你做的，哪些是开发者做的

**素材编写者（你）需要做**：

- 在 `materials/` 下编辑/新建 JSON 文件。
- 写角色（`characters`）、台词（`lines`）、场景台词（`scenarios`）。
- 保证 JSON 格式正确、角色 `id` 不重复、台词引用的 `id` 存在。

**程序开发者需要做（你不用管）**：

- 素材如何被程序加载、校验、转换成字幕事件；
- 七种测试场景的节奏、时间轴、说话人分配；
- 新增素材包的自动发现、多包切换、随机抽取等功能（尚未实现）。

一句话：**你负责「写什么」，程序负责「怎么说、什么时候说」。**

# 截图暴露密钥的检查与安全轮换方案（2026-11-01）

本文件仅记录用途、顺序和验收，不记录实际密钥、摘要或授权码。已按用户说明将截图中的账号密钥及房间管理密钥视为已暴露；本轮邮箱上线保留原值，**尚未执行轮换，风险尚未消除**。

## 已检查的实际用途

- `XDSTAR_ACCOUNT_SECRET`：Fastify Cookie 签名器、CSRF Cookie 签名和 CSRF userInfo HMAC，同时用于限流/注册来源 subject 的 HMAC。
- 当前 `__Host-xdstar_session` Cookie 是32字节随机令牌，`issueSession` 没有设置 `signed:true`，数据库按 SHA-256 摘要查找；会话有效性还检查 auth_version、绝对期限及闲置期限。账号密码是独立 Argon2id 哈希。**更换账号密钥本身不改变原会话令牌或密码**；此前文档笼统称“更换账号密钥会让旧会话失效”不符合当前会话实现，以下述分用途方案为准。
- `HAKISUB_ROOM_MANAGEMENT_SECRET`：账号端签名、网关端验签，绑定 POST 路径及完整正文；网关另检查本次启动 audience、10秒时间窗及共享 nonce 去重。用于房间管理和账号入房授权。当前两端仅支持单密钥，改一端会导致服务认证失败。
- 两份服务器秘密环境文件权限均为 root:0600。针对当前 tracked Git 源码快照，在服务器内存中与实际环境值比对，账号密钥、房间管理密钥及SMTP授权码均未匹配到明文。此检查**不涵盖 Git 历史、截图、聊天、个人下载或外部日志**，不能证明暴露已经消除，也不能以改写Git历史撤销泄露密钥。

## 第一优先：账号密钥分用途轮换

1. 在服务器用安全随机源生成独立的新 CSRF/Cookie 密钥及限流密钥，写入 root:0600 文件，禁止打印、截图或传入命令行字面量。保留加密配置快照用于受控恢复。
2. 先增加独立的 `XDSTAR_RATE_LIMIT_SECRET` 配置，所有来源 subject、注册配额和相关管理员 CLI 一致使用它；迁移阶段将它设置为当前旧账号密钥，保持现存限额索引。该旧值只暂用于不可逆 subject 计算，不再参与CSRF签名/验证，不作为认证密钥。
3. 将 `XDSTAR_ACCOUNT_SECRET` 切换为新值，只重建账号容器；不清空 sessions，不修改 auth_version、不改用户密码和 UID。拒绝旧 CSRF Cookie/令牌，GET csrf 会自动生成新 Cookie 和令牌，现有客户端每次写请求前已会重新获取。并发中的旧写请求可能一次403，刷新重试即可。**不为已泄露的旧CSRF密钥设置长期兼容验证窗口。**
4. 验证原会话 Cookie仍可读取 me/存档/自有房间，原密码仍可用；旧 CSRF 写请求403，获取新 CSRF 后写请求恢复；过期/撤销会话仍拒绝。新增 `accounts/tests/key-rotation-readiness.test.mjs` 在隔离SQLite验证了会话、原密码、旧CSRF拒绝与新CSRF恢复，并明确证明直接换密钥会改变限流subject。
5. 等旧窗口自然到期后，再轮换独立限流密钥。当前最大身份配额窗口为24小时；由于只保存HMAC，不能从旧subject重算新值。上线前需选择24小时双subject合并计数，或在限制新注册/发送的短窗口中切换并记录额度重置，避免未声明地绕过配额。旧待验证注册令牌中也保存了原subject，应纳入跨subject配额处理；超过令牌30分钟期限后再移除旧subject兼容。管理员 clear-ip须同步测试。

这需要一次小规模后端实现与模拟测试，然后才安排实际轮换；本次未提前配置不存在的环境选项。

## 第二优先：房间管理密钥协调轮换

推荐先实现很短的双密钥验证窗口，再迁移签名端，避免单边替换：

1. 网关增加带明确失效时间的当前/过渡密钥环；保持每个请求只执行一次业务授权、共用同一个 nonce 去重缓存，不能按密钥分别去重。跨密钥重放、过期旧密钥、错误 audience、伪造签名必须拒绝。
2. 网关先接受新密钥和短期旧密钥，账号再改为只用新密钥签名；验证双方 list/access 及所有管理动作授权。旧密钥已泄露，过渡窗口应尽量短（例如30～60秒），不得永久保留。
3. 删除旧密钥的验签能力，验证旧签名拒绝、新签名通过，旧UID/ownerUid/房间密码摘要/账号会话和存档不变；不得重建房间或重新绑定所有权。
4. 目前网关将密钥闭包固定在启动时，没有热更新。直接靠重建网关应用密钥会断开WSS并清空内存房间ASR Key，这是当前设计的重启行为，不能宣称零影响。若要求不中断现有房间，应先实现受限文件密钥环的原子热加载与失败保留旧配置；不新增公网管理端点。否则必须提前安排维护窗口，通知房主重新填写ASR Key，并验收客户端安全重连；不得偷偷重启网关来轮换。
5. 轮换故障优先向前修正新密钥配置。只在必要的短暂维护期间允许受控恢复，不能长期恢复使用泄露密钥，也不能通过取消签名检查恢复服务。

## 收尾与范围

实际轮换后记录密钥版本标识（非密钥值/摘要）、切换时间和验收；保留备份解密所需历史加密材料的受限归档，避免误删导致备份不可恢复。撤销截图/聊天中可撤销的共享访问，检查异常管理及认证事件。现有审计日志并不完整，不能据此断言从未被滥用；如另有会话令牌或SMTP授权码也暴露，应分别撤销对应会话或重新生成QQ授权码。

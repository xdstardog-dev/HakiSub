## 部署与恢复

沿用 hakisub-server、既有 Compose、卷、凭据及 Caddy。候选镜像复用现用 Node 22 Linux 依赖，仅替换应用文件。白名单运行包和 Git 提交源码分别归档，逐文件校验 SHA-256。准备阶段生成并实际解密核验服务器同机加密备份，在无网络、无生产卷和凭据的候选容器中测试，并以房间备份副本演练 v5 迁移。

切换前停止账号和网关，通过 SQLite backup API 与房间文件生成一致性备份，再配套更新两个发布选择器并启动。旧镜像和备份保留；自动回退只允许尚未写 v5。出现 v5 后拒绝不兼容旧网关，保留数据并优先向前修复。灾难恢复必须停止写入、先备份当前状态，再明确选择成套恢复旧镜像和切换前数据；不可直接让旧网关读取 v5，亦不可用旧快照覆盖新写入资料。

# 2026-11-01 完整版本发布

## 范围与版本边界

发布编号 `room-ui-20261031T1745Z`。用户明确授权推送 GitHub 和部署生产。包含首页及房间卡片、房名与账号昵称规则、私密建房、设置与字幕入场提示音、本人回应、头像及统一 PIN 输入；配套更新网关、账号后端及两套前端。

房间密码迁移为带盐 scrypt 摘要，房间资料写 v5，保留房号、别名、房主、名称、访问版本及已授权账号。已保存的 Key 不可回读，仍仅进程内存有效，重启由房主重填。账号 SQLite 仍为 schema v2。

## 发布前验证

`npm test`、`npm run test:accounts`、`npm run test:room-management`、`npm run build`、`npm run build:accounts` 通过。Chrome 首页、房间 UI、头像、模拟设置、PIN 入房、成员控制、账号工作台七组回归通过。

修正 room-key-memory 的旧断言，补入既定默认头像 home；账号工作台浏览器脚本验证仅显示新输入的 Key、保存清理和禁止明文回读。首轮沙箱限制 esbuild 与房号 CLI 子进程，正常权限重跑通过。

## 部署与恢复

沿用 hakisub-server、既有 Compose、卷、凭据及 Caddy。候选镜像复用现用 Node 22 Linux 依赖，仅替换应用文件。白名单运行包和 Git 提交源码分别归档，逐文件校验 SHA-256。准备阶段生成并实际解密核验服务器同机加密备份，在无网络、无生产卷和凭据的候选容器中测试，并以房间备份副本演练 v5 迁移。

切换前停止账号和网关，通过 SQLite backup API 与房间文件生成一致性备份，再配套更新两个发布选择器并启动。旧镜像和备份保留；自动回退只允许尚未写 v5。出现 v5 后拒绝不兼容旧网关，保留数据并优先向前修复。灾难恢复必须停止写入、先备份当前状态，再明确选择成套恢复旧镜像和切换前数据；不可直接让旧网关读取 v5，亦不可用旧快照覆盖新写入资料。

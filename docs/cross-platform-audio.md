# 跨平台语音与自动停止上传

确认日期：2026-10-15（Asia/Shanghai）。本文区分已实现行为、用户测试反馈和后续设计，不表示已完成公网部署或安卓适配。

## 已确认的产品要求

- 产品以豆包识别为默认路线，真实输入的初始来源已设为豆包；保留浏览器 ASR 和模拟模式，页面默认真实联网房间，但必须手动开麦；本地模拟仍可选。
- 用户在断续讲话测试中观察到自动结束上传能明显节省用量。网页版和安卓 App 都必须保留这项核心能力，不能因换浏览器、网页容器或原生采集而退化为全程上传静音。
- 手动开麦后，本地持续检测；讲话时才建立豆包会话并上传；持续安静后结束该会话、停止上传；再次讲话自动恢复。
- “自动断开”指结束云端识别连接与上传。本地麦克风继续监听，才能感知再次讲话。手动关麦、离房或结束使用时完整释放采集、缓存及连接。
- 底层持续采集、上传前静音判断和句首保护是三个独立职责：静音判断只能控制上传，不能通过关闭底层麦克风来实现等待说话。
- 句首保护适用于首次讲话及每次静音后的重新开口，而不只是第一次开麦。等待时维护仅在内存中的短时滚动音频缓冲；触发时按顺序补送触发前音频与触发包，再接实时音频。建连及旧会话收尾期间继续有界缓存新讲话，不能等连接就绪后才开始采集，也不能重复补送或无限积压。缓冲不落盘，不构成录音历史。
- “静音不上传”指安静等待时不持续发送空白音频，不要求剪除每一帧静音；句首前置缓冲、尾音保护及短暂停顿允许包含有限静音。检测阈值不能以截掉首字或尾音为代价追求省费。
- 不把本地上传秒数、豆包返回时长或账户显示差值直接等同于精确计费。省费比例需在相同条件下实测，不承诺只按有效讲话时间收费。

## 当前实现与限制

`audioCapture.worklet.js` 在音频线程主动发送样本；AudioContext 按设备默认采样率采集，`audioResampler.ts` 形成 16kHz 单声道 PCM。`speechDetector.ts` 将副本交给独立 Worker，`sileroVadModel.ts` 以官方 Silero v6 模型按512新样本及64历史样本计算人声概率，保留循环状态和跨包余样本。`voiceActivityGate.ts` 以每200ms包的最大概率判断起止，开始/续讲门槛分别为0.5/0.35。触发前保留约500ms缓冲，默认持续静音约1.6秒后触发结束。`doubaoAsrClient.ts` 管理有序音频与结束标记，等待旧连接实际关闭再建立下一段。

这一过程不使用浏览器 `SpeechRecognition` 来判断静音，原简单音量判断已被模型概率替代。模型仍可能误检或漏检，也不能自动区分当前用户和电视等其他人声；实际轻声、噪声和中文短字需真实验收。当前已完成网页实现，安卓尚未适配。

检测器一次只派发一个推理任务，保留原PCM供句首补送。启动前及推理期间最多暂存25个200ms包；启动超时20秒、单包推理超时3秒、积压或音频超过5秒未处理时停止识别并释放麦克风、Worker和云端连接。停止后忽略迟到结果。模型与固定版本ONNX Runtime Web从同源加载，无外部CDN、无检测服务音频上传，单线程WASM不要求跨源隔离。资源来源、SHA-256与许可证见 [VAD资源说明](../public/vad/README.md)。

README 中“浏览器 ASR 的 800ms 静音断句限制”描述的是可选 Web Speech API 路线的能力限制，并不表示已实现 800ms 判停。未来即使把本地静音阈值设为 800ms，最终字幕仍受包长、网络、云端处理和最终响应影响；本地判停也不能擅自将临时字幕标记为 Final。

## 可以摆脱哪些环境依赖

可以摆脱浏览器自带语音识别和它的断句策略：在设备上对 PCM 运行自有检测，再由统一会话控制决定是否上传。检测本身可离线运行，豆包转写仍需联网。

不能完全摆脱运行环境：网页需要安全上下文、麦克风授权及可用的音频采集接口；模型还需要相应推理运行时。安卓需要原生录音权限和生命周期适配。浏览器冻结、系统休眠、进程被终止时，本地检测无法继续，不应承诺锁屏或后台无限运行。

AudioWorklet 主动出块能降低对页面定时器的依赖，但后续消息处理仍可能延迟，也不能阻止浏览器或系统暂停音频图。安卓若要求持续后台采集，应单独设计符合平台规则的麦克风前台服务和恢复行为；仅用 WebView 包装网页不能证明已经满足要求。

## 开源方案参考

### EasySub：采集与音频线程主动出块

核对了 [仓库说明](https://github.com/easysub-org/easysub)、[mic-capture.ts](https://github.com/easysub-org/easysub/blob/master/src/mic-capture.ts) 和 [audio-worklet-processor.js](https://github.com/easysub-org/easysub/blob/master/public/audio-worklet-processor.js)。

其采集层分离宿主差异，允许由 Worklet 按累计音频帧主动推送音频，而非依赖主线程定时请求 flush；还处理异步启动与停止竞态、设备断开和 AudioContext 无法启动。采集使用设备默认采样率，输出时重采样；源码记录了强制 16kHz AudioContext 的跨浏览器问题，值得作为 HakiSub 后续兼容性测试项目。

这两个文件负责采集和出块，并不直接提供 HakiSub 所需的豆包静音断流控制。HakiSub 已有 Worklet 主动输出方向，可以参考职责划分和故障收敛，不需要为此引入整套离线转写模型。EasySub 的离线 ASR 与本文讨论的“小型 VAD + 豆包云端转写”是不同路线。未移植 EasySub 源码；HakiSub 已改用设备默认 AudioContext 采样率并在输出层重采样，另行接入 Silero 与 ONNX Runtime Web。

### Silero：设备端语音活动检测候选

[Silero VAD](https://github.com/snakers4/silero-vad) 提供语音活动检测模型，支持 8kHz/16kHz；官方说明列出了 ONNX 可移植路线、浏览器 ONNX Runtime Web 社区示例及多语言示例。它可作为独立于 Web Speech API 的人声判定候选，而非豆包转写的替代品。

网页已选用固定 Silero v6 模型和 ONNX Runtime Web 1.24.3，以本地WASM推理判定语音；安卓后续使用兼容的原生推理运行时与原生采集，共享模型版本、阈值含义、静音尾部与起始缓冲规则。安卓运行时尚未选择。模型与运行时须适配并实际测试，不是将 Python 示例直接放进网页。需验证噪声、轻声、短字、电视人声、CPU、耗电与加载失败；VAD 不会自动识别“是不是当前用户在说话”。

## 网页已实现结构与后续迁移

音频链路：平台采集适配器 → 单声道 PCM/重采样 → 设备端 VAD 与起始缓冲 → 上传会话状态机 → 网关 → 豆包 → 统一字幕事件。

状态机明确区分本地等待、建连缓存、上传、等待尾部结果、旧连接关闭和故障停止。保持音频包与结束标记有序，避免丢句首、截尾音或重连后重复上传；以音频样本数量累计静音时长，减少页面定时器延迟对判停的影响。缓冲必须有上限；恢复后不无限补传过时的音频。

可再评估网关端 VAD 作为第二道保护：即使客户端错误地持续发送静音，网关也能停止向豆包发送。但此方案仍有设备到网关的流量，增加服务器算力与音频处理范围，不能代替设备端检测；也无法在设备已停止采集时恢复声音。当前网关尚未实现声学 VAD，只已有无音频超时、结束等待超时和会话上限。

检测运行时缺失、模型加载失败或采集不可用时，当前网页会明确提示并停止识别，不退化为全程上传。若以后保留持续上传的替代模式，应让用户明确选择并告知用量影响。

## 迁移验收要求

1. 纯静音不开豆包连接，底层仍持续本地采集与判断；首次讲话及每次重新开口的句首、短字均保留，覆盖触发前、建连中和旧会话收尾时开口；补送有序且不重复，短暂停顿不频繁误切断。
2. 持续静音后停止向豆包发送，按协议收尾并释放上游连接；重新讲话能恢复，尾部 Final 保留且无重复音频。
3. 手动关麦、离房或结束使用后释放采集和连接，迟到的异步结果不能重新开启上传。
4. 在目标浏览器及安卓真机分别验证前台、切后台、锁屏、断网、权限撤销、设备断开及恢复；被系统暂停时如实提示状态，网关超时关闭上游，不承诺持续采集。
5. 用上传字节/秒数、各会话状态和真实账户用量对照确认静音断流。区分设备到网关和网关到豆包的音频；模拟通过不能替代麦克风、系统后台和真实云端验收。

网页实现已接入模型；未公网部署、打包或调用真实语音服务。真实麦克风、安卓后台和真实账单验收仍须单独记录。

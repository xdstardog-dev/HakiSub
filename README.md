# HakiSub 实时字幕

基于 Vue 3、TypeScript、Vite 的实时字幕软件，用于日常面对面交流，按成员显示字幕。字幕只在当前页面内存中短暂存在，不保留历史，不提供暂停、冻结、回看或摘要。刷新、离开房间即清空。

## 启动与验证

建议 Node.js 22.12+。Windows 可在项目文件夹打开 PowerShell 执行：

```bash
npm ci
npm run dev
npm test
npm run build
```

`npm run dev` 同时启动网页（`http://127.0.0.1:5173`）和本地语音网关（8787）。请在 Chrome 打开网页，保持终端运行；Ctrl+C 关闭两项服务。端口被占用时先关闭旧服务。此次网关只面向本机使用。

`npm run build` 包含 TypeScript 检查，产物在 `dist/`。`npm test` 包含原有测试和豆包模拟测试，不调用真实付费 API。要预览构建产物，分别运行 `npm run server` 和 `npm run preview`，访问 `http://127.0.0.1:4173`。

## 配置豆包 ASR 2.0

1. 在火山引擎豆包语音控制台开通「豆包流式语音识别模型 2.0」小时版，确认 API Key 有 `volc.seedasr.sauc.duration` 的调用权限及可用额度。
2. 首次克隆后将根目录 `.env.example` 复制为 `.env`（已有 `.env` 时不要覆盖）。在本地编辑：

   ```dotenv
   DOUBAO_API_KEY=在这里填写你的真实APIKey
   ```

3. 重启 `npm run dev`。Key 只由 Node.js 网关读取，不需要填写到网页；不要使用 `VITE_` 前缀、不要将 Key 发进聊天或提交 Git。`.env` 已被忽略；`.env.example` 保持空值。
4. 输入名字进入房间 → 输入选择「真实麦克风」→ 识别来源选择「豆包 ASR 2.0」→ 点击「开启麦克风」并允许权限。等状态显示已开启后讲话。

麦克风音频经本地网关发送到豆包云端；这不是离线识别。临时文字在原位置更新，供应商确认 Final 后才启动既有渐隐计时。应用不保存音频文件或识别历史，也不记录密钥、音频、完整识别响应。

停止、切换来源、切换模式、隐藏页面、离房或断线会关闭采集和云端连接，丢弃未确认字幕，已确认字幕自然过期。停止属于取消，不等待最后一句补完；最后不足 200ms 的本地音频被丢弃。豆包模式没有自动重连，上传积压/音频传输中断会停止；单次最多 15 分钟，需手动重新开启。当前持续上传包括静音，不做本地 VAD、省费优化或降噪。

浏览器 ASR 和模拟字幕仍可在没有 Key 时使用。房间尚不支持多设备联机，只有「我」采集真实音频。

### 怎样验收豆包识别

1. 连续说一句较长的话：应逐步出现文字且不新增重复行。
2. 停顿后继续第二句：第一句确认后渐隐，第二句单独显示；文字长短仍遵循下方 3/6/10 秒规则。
3. 点击关闭麦克风后继续说话：不应新增文字，Chrome 麦克风占用应释放。在开发者工具 Network 中 `/api/asr` 连接关闭，不再发送音频帧。
4. 测试拒绝权限、断网、切换来源、离开房间和隐藏页面：应停止并在适当位置提示，不能无限重连。
5. 切回浏览器 ASR 和模拟模式检查原有流程。不要将模拟测试通过当作豆包真实调用验收。

当前没有配置真实 API Key；真实账户权限、麦克风识别、准确率、延迟和长时间稳定性均待用户实测。

### 常见错误

| 提示/现象 | 处理方法 |
| --- | --- |
| 尚未配置 API Key | 编辑根目录 `.env`，填写 `DOUBAO_API_KEY`，重启服务；不是 `.env.local` |
| 无法连接本地网关 | 使用新的 `npm run dev` 同时启动网页和网关，关闭旧的 Vite 进程 |
| HTTP 401/403 或服务拒绝 | 检查语音服务 API Key、ASR 2.0 小时版权限、账户额度；普通聊天模型的 Key 不一定有语音权限 |
| 麦克风被拒绝 | 在 Chrome 地址栏的网站权限中允许麦克风，检查 Windows 麦克风权限 |
| 连接超时/断开 | 检查能否访问豆包语音服务，再手动开启；Git 的代理配置不控制 Node.js 网关 |
| 一直不出字 | 确认使用正确输入设备，等“已开启”再讲话；先核对控制台权限及页面错误提示 |
| 15 分钟上限 | 单次会话已停止，需手动重新开启 |

架构见 [ARCHITECTURE](docs/ARCHITECTURE.md)，实际开发和验证记录见 [DEVLOG](docs/DEVLOG.md)。

## 保留的固定分屏

按成员 ID 和加入顺序固定位置，发言不改变顺序：

| 人数 | CSS Grid 布局 |
| --- | --- |
| 1 | 1 列 1 行 |
| 2 | 1 列 2 行，上下等高 |
| 3 | 2 列 2 行，首位成员占满第一行 |
| 4 | 2 列 2 行等分 |
| 5 | 2 列 3 行，首位成员占满第一行 |
| 6 | 2 列 3 行等分 |
| 7 | 2 列 4 行，首位成员占满第一行 |
| 8 | 2 列 4 行等分 |

每张卡片独立显示多句，旧句在上，新句在下。第一句从内容区域顶部开始，未溢出时按正常文档流向下排列，不滚动。仅当内容高度超出可视区域时，自动滚动到底部显示最新字幕；不提供手动翻阅。移除旧句后自然重排，内容不足一屏时恢复顶部对齐。内容增长、删除、卡片尺寸或字体变化时均重新判断是否溢出，房间高度固定为视口高度。

每位成员最新出现的一句话（含 Interim）使用标准字号的 100% 和 700 字重；其他句子使用标准字号的 88% 和 400 字重。新句出现时上一句立即切换为历史样式，新句消失后不会回退加粗旧句。

## 动态卡片布局实验

房间中的复选框在“固定等分布局（原版）”与“动态自适应布局（实验）”间切换，默认关闭，运行模拟时也可随时对比。原有固定 Grid 规则保留。

动态模式读取每张卡片当前字幕流的实际高度（包括尚未过期的 Final 和 Interim），以 32px 高度分桶并限制需求权重。先预留约 80px 的最小空间（依据标题高度增加），再把剩余空间按需求分配；可用空间不足时取消额外分配并收紧卡片内边距与麦克风按钮，让姓名和状态优先可见。左右两列独立分配高度，成员不按活跃度排序，3/5/7 人的第一位继续横跨两列。

内容引起的尺寸调整每 600ms 最多一次，小于 12px 的变化忽略；均衡恢复不受该阈值阻挡。高度和顶部位置使用 300ms 过渡。视口大小或成员人数改变时重新计算，内容始终限制在房间可用区域内，保留卡片内部从顶部开始、溢出后跟随最新字幕的逻辑。

本次已用 Chromium 在 320×568、390×844、480×720 视口实测 1～8 人动态布局的卡片边界、无重叠和标题可见性，并验证 8 人内容扩张、历史/最新字号、溢出跟随、固定/动态切换和过期后均衡恢复。浏览器测试工具临时安装于 `/tmp`，未添加项目运行依赖。

对比建议：8 人房间运行“卡片内容溢出”，观察首位成员增高、同列其他成员收缩；运行“1 分钟压力测试”对比密集与稀疏阶段；待字幕过期后检查均衡恢复；期间切换固定/动态模式，字幕计时不会重置。

## 字幕生命周期

| 最终字数 | 完整显示 | 渐隐 | 总时长 |
| --- | --- | --- | --- |
| 1～15 | 3 秒 | 2 秒 | 5 秒 |
| 16～30 | 6 秒 | 2 秒 | 8 秒 |
| 31 及以上 | 10 秒 | 2 秒 | 12 秒 |

字数采用 Unicode 字符计数，排除标点和空白；中文逐字计数，混合文本中的字母、数字等也计入。每句 Final 保存独立的确认时间和显示时长。共享 50ms 时钟计算各自透明度及清理，不会因新句到来而重置旧句。后台页面恢复后按实际时间清理，不延长过期字幕。

`recognize(memberId, utteranceId, text, state)` 是当前识别事件入口。同一句的 Interim 和 Final 使用相同且稳定的 utteranceId；下一句使用新 ID。Interim 原位更新且不计时，Final 才开始生命周期，队列中重复 Final 不会重置时间。实际识别服务接入时需保证每人一句一个唯一 ID 并按顺序投递。关闭模拟麦克风会丢弃未确认的 Interim，已确认的 Final 继续自然过期。

## 手动测试

输入显示名称进入房间，在“模拟字幕”下拉框选择场景后点击“运行”。测试期间字幕照常消失，当前场景结束后可再次运行。普通场景使用第一位已开启模拟麦克风的成员；8 人场景和一分钟压力测试自动补齐成员并开启所有模拟麦克风。

1. **单人连续快速讲话**：700ms 间隔加入三句，确认三条共存、分别消失。
2. **8 人同时讲话**：8 人同时各发一句，900ms 后各追加一句，确认字幕互不干扰、位置不变。
3. **长句（超过 30 字）**：确认完整显示 10 秒，之后渐隐 2 秒。
4. **渐隐时加入新句**：短句出现 4 秒后追加新句，此时前句约半透明，新句仍完整显示。
5. **卡片内容溢出**：每 100ms 添加一句，共 20 句。切换 1～8 人，确认最新句在底部、旧句裁切，滚轮、触屏及键盘无法翻阅旧内容，页面不被撑高。
6. **实时识别到确认**：每 250ms 增长一次同一条字幕，正文不附加状态文字；确认后按最终字数开始计时，随后追加新句。

7. **8 人对话 · 1 分钟压力测试**：自动补齐 8 人，以周末出行讨论为主题，共生成 81 句。每 10 秒交替密集发言（24 句）和稀疏发言（3 句），覆盖短、中、长三档字幕，以及多人重叠发言。每句先经历四次 Interim 更新，再确认 Final。底部显示秒数进度及当前节奏；60 秒结束发言后，剩余字幕按原生命周期自然消失，最长再等待 12 秒。期间固定演示人数为 8 人，麦克风仍可独立切换，离房会取消后续事件。脚本固定，便于重复对比性能与布局。

建议浏览器以 320px、390px、480px 宽度及不同高度检查所有人数布局。自动测试覆盖字数边界、渐隐边界、新旧句独立计时、Interim 到 Final、重复确认、成员隔离、静音、人数变化、六种基础模拟、一分钟压力测试及离房/卸载清理。

## 单设备浏览器 ASR（保留功能）

房间上方“输入”可切换“模拟字幕”和“真实麦克风”。真实模式点击“开启麦克风”才请求权限；默认保持模拟模式，不自动采集。识别语言为普通话 `zh-CN`，只写入“我”的卡片，其他成员显示“未接入设备”。浏览器通过 Web Speech API 自行采集麦克风并执行识别，没有额外创建 MediaRecorder 或重复的 getUserMedia 音轨。

每次识别会话与结果索引组合成稳定句子 ID，Interim 原位更新，`isFinal` 确认后交给原有 3/6/10 秒显示和 2 秒渐隐规则。浏览器决定断句，不能保证按每个中文标点分句。重复 Final 被过滤，识别器撤回的 Interim 会移除。停止时丢弃未确认字幕，保留已确认字幕自然过期。

关闭麦克风、离房、切回模拟、页面隐藏或离开页面时会 abort 识别并清除重连任务；再次回到页面需要手动开启。切换输入模式清空当前字幕并取消模拟调度，避免混入两种来源。浏览器正常结束会话或无语音时最多连续重试两次，收到结果后重置重试次数；授权、网络、设备等错误立即停止并提示，不无限重试。重连期间可能漏掉语音，不做音频缓存或补录。

### 方案、兼容性、延迟与费用

- 使用 `SpeechRecognition` / `webkitSpeechRecognition`，启用 `continuous` 和 `interimResults`。优先在桌面 Chrome 验证；Safari 有实现但依赖系统语音配置。其他浏览器、手机和内嵌 WebView 以能力检测和实际服务可用性为准，不把接口存在视为识别成功。
- 使用 HTTPS 或本机 localhost。Codespaces 应从端口面板打开独立的 HTTPS 浏览器标签页；HTTP 局域网 IP 不适合手机麦克风测试。内嵌预览可能受权限策略限制。
- 临时结果 0.5～2 秒、停顿后 1～3 秒确认仅为工程验证目标，尚未实测，也不是浏览器服务 SLA；网络、设备、句长和服务断句会改变延迟。
- 此实现无需 API 密钥，没有配置付费 ASR 账户或按量计费接口；网络流量可能产生费用。浏览器识别服务的可用性和限制由浏览器厂商决定。
- 浏览器可能把音频发送到其在线识别服务，例如 Chrome 的服务端识别。当前网络无法访问服务时会报错，不能保证离线或所有地区可用。应用自身不录音、不保存或上传音频到应用服务器；浏览器服务的数据处理不由本应用控制。页面内存字幕过期不等于远端服务的数据删除承诺。
- 现在也可选择上文的豆包模式，其麦克风采集和连接由独立模块负责，密钥仅由本地网关读取。

参考：[Chrome Web Speech API](https://developer.chrome.com/blog/voice-driven-web-apps-introduction-to-the-web-speech-api?hl=en)、[Safari 语音识别](https://webkit.org/blog/11648/new-webkit-features-in-safari-14-1/)、[MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。

### 真实设备验收

1. `npm run dev`，在独立浏览器标签页打开 HTTPS 转发地址（本机可 localhost）。创建房间并选择“真实麦克风”。
2. 点击“开启麦克风”，允许权限，确认状态从请求授权变为“麦克风已开启 · 普通话”。
3. 连续说几句普通话并在句间停顿，确认临时文字在同一句更新，Final 后开始独立渐隐，下一句另起一条并加粗。
4. 关闭麦克风后继续讲话，确认没有新字幕，浏览器停止采集；已确认字幕继续自然过期。
5. 分别测试拒绝授权、浏览器禁用麦克风、断网、切换输入、切后台及离房。恢复权限或网络后点击开启重试。
6. 切回模拟模式，再运行一分钟压力测试，对比卡片行为。

自动测试使用假识别引擎，可验证事件与状态逻辑，不能证明实际硬件、浏览器服务、识别准确率或延迟。当前开发环境尚未完成真实麦克风听写验收。

## 当前模拟范围

房间创建/加入、其他成员及模拟模式的麦克风开关和字幕仍为本地演示。加入接受任意 6 位数字码，创建随机生成 6 位码；不同设备或标签页不互通。真实模式可选择浏览器识别或豆包 ASR，不涉及八人联机、外接麦克风路由或降噪。`/glasses` 仍为静态概念预览，未连接眼镜硬件。

## 浏览器 ASR 的 800ms 静音断句限制

当前使用浏览器 Web Speech API，由浏览器自行控制断句。接口没有静音阈值配置；`continuous` 不等于自定义断句，`speechend` 不是可配置为 800ms 的 VAD。当前没有独立 VAD，也没有用“800ms 未收到文字”作为静音判断。参见 [Web Speech API 接口规范](https://webaudio.github.io/web-speech-api/#speechreco-section)。

正文和成员状态栏已移除“识别中／正在识别”文字，保留麦克风开关、未接入设备和权限错误信息；原有字体层级、布局、滚动与字幕生命周期未改动。

浏览器模式的原方案及限制见 [音频断句方案](docs/audio-segmentation.md)。豆包模式启用云端二遍识别以获取确定分句，采用服务默认判停；不等同于本地 VAD 或精确 800ms 的端到端字幕延迟承诺。0.3/0.6/0.9 秒真实音频停顿、多次犹豫、长对话和连续 10 分钟场景均待真实验收。

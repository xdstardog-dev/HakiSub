## 四位房间密码输入（2026-11-01，本地完成，未部署）

私密建房、房内设置／更换密码、加入与错误重试、模拟模式设置，以及账号中心的入房码设置，统一使用无边框 PIN：空位显示灰色 `●`，已输入的位置显示数字，整排居中。只接收四位 0–9，保留前导零；支持退格、全选与粘贴，手机通过原生 `inputmode="numeric"` 请求系统数字键盘。四位输入完成后由原确认按钮提交，未满四位不能确认。保存、取消或重新打开时沿用原清理流程，不回显已保存密码；模拟设置也只显示已设置状态。

组件位于 `accounts/shared/PinCodeInput.vue`，供主站和独立账号前端共用；房号、分享码、账号密码及服务端密码规则不变。浏览器验收入口为 `test:room-access:browser`；账号中心可运行 `node accounts/tests/workspace-browser.mjs <Playwright模块路径> --pin-only`。手机尺寸仿真可检查触屏焦点与布局，物理手机的系统键盘仍需真机验收。

## 房间内部 UI 重构（2026-10-31，本地完成，未部署）

点击顶部房屋图标进入设置。普通设置为独立的「发言提示音」「快捷回复音效」两条0～100%音量和「动态自适应／固定等分」布局，均只影响本机并保存到localStorage；新用户默认动态布局。房主另有ASR开关及「房主设置」二级页，集中管理名称、Key和四位密码。房间名与六位房间号分开，继续使用现有服务端校验、持久化与广播。房内移除个人存档入口和普通技术参数，账号及存档数据保留；明确追加 `?debug=1` 后才显示原浏览器ASR切换、布局对比与详细MP3试听工具，便于回归。

每名成员在本房会话内由服务端分配0～7的稳定toneSlot，对应C4、D4、E4、F4、G4、A4、B4、C5；离房释放最小空闲槽，不重编号其他成员。只有该成员所有字幕及渐隐已完全结束后，再出现首条非空语音字幕，才由同一个事件触发两圈头像涟漪、一次1.015倍卡片呼吸和短音。interim更新、final确认、尚有字幕时的新句、打字、回应和布局切换均不会重播；打字内容也计入占位。静音保留动画，减少动态效果时跳过动画，音频未解锁则丢弃而不补播。

**此版本改变旧密码／密钥回读规则：** 房间Key保存后立即清空输入，只显示掩码；更换时使用新的空白明文输入框，房间与账号管理接口均拒绝原文回读。Key仍仅存服务端进程内存，重启需重填。房间密码改存带随机盐的scrypt摘要，房间资料写入v5；加载旧v1～v4含密码记录时原子迁移并保留房主、名称、别名、访问版本和已授权账号。输入支持0000，启用前必须成功保存四位ASCII数字，错误5次／分钟限制及账号免输流程保留。**前后端需配套发布；旧程序不能读取v5资料，不能直接回退旧镜像。** 本次没有操作生产数据。

已通过自动化、隔离网关和Chrome浏览器测试；手机／桌面共用最大480px窄框。完整改动文件、测试结果、兼容边界及人工验收项见[本次验收记录](docs/ROOM-UI-REFACTOR-20261031.md)。截图见 `artifacts/room-refactor/`。真实麦克风／豆包、物理手机／Safari及扬声器听感仍需单独验收。

## 角色收束与输入切换（2026-10-30实现，10月31日已部署）

成员同时满足**闭麦、没有任何可见字幕**时开始连续计时，满5秒后收起到底部一排头像。出现任何字幕（包括渐隐中的文字）都会清零，等文字完全消失后重新计算完整5秒；开麦、打字、麦克风准备/错误及正在操作菜单时不收起。头像显示名称和闭麦标记，窄屏横向滚动；仅点击自己的头像可展开并重新计时，保持闭麦；点击/轻触他人的头像不展开，只能长按或右键发送快捷回应。开麦、进入打字或收到新字幕立即恢复卡片，保持成员原顺序。全员收起时仍可通过自己的头像或底部常驻控件恢复本人卡片；头像可继续右键/长按回应并显示回应标记。键盘焦点保护卡片，鼠标/触摸点击闭麦后留下的普通焦点不会阻止收束。

## 网页版与安卓 App 的共同要求

麦克风开启时，卡片显示“麦克风准备中…”、按钮显示“取消开启”；页面依次显示运行库加载、资源下载百分比、模型初始化。本地模型与采集均就绪后才显示“麦克风开启 · 等待说话”，请在就绪后再讲话。首次模型与WASM原始约14.7MB，正式服务器预压缩后约5.1MB；公开资源按模型及运行库版本缓存。下载持续有进度即可继续等待，30秒无进展、初始化超过60秒或整个准备超过180秒才报错；麦克风权限/采集单独限30秒。加载期间只保留最近约600ms，不补识别等待期全部音频；运行期积压保护保留，检测失败不退回持续上传。2026-10-20先修复了加载超过5秒的积压误判，随后修复20秒统一加载时限与无进度提示的问题。

网页到语音网关发生短暂传输故障时，保持采集并显示“正在恢复”，30秒内最多尝试两次（间隔250ms、750ms）；已交给旧连接的音频不重放，未确认的中断片段可能不完整。没有待发送语音时继续本地等待，不为空重连建立豆包会话。手动关闭/离房会取消恢复；多次失败、服务配置/额度错误、模型或采集故障仍停止并提示。正常结束的旧识别立即释放成员与并发名额，不等待WebSocket关闭握手，避免下一句被误拒；同一成员仍只能有一路有效识别。不会再提示线上用户运行npm run dev。用户确认现有不到一秒的体感延迟可接受，识别参数、200ms包、句首保护和静音收尾保持原值。

产品默认识别路线为豆包；浏览器 ASR 保留为可选能力，页面默认真实联网房间，仍不自动采集。用户测试反馈表明，讲话结束后自动停止向豆包上传音频能明显节省用量，因此“本地等待说话 → 讲话时上传 → 静音后结束云端会话 → 再次讲话自动恢复”是网页版和安卓 App 必须保留的核心行为，不能依赖 Chrome 或 Web Speech API 的断句能力。

核心要求是“底层麦克风持续本地采集 + 上传前静音判断 + 每次开口的句首保护”。检测到讲话时，先补送本地短时滚动缓冲，再接上实时音频；建连期间继续有界缓存，保护首次讲话及每次静音后重新开口的第一个字。静音不上传指等待状态不持续上传空白，允许为句首保护、尾音和短暂停顿保留有限音频。手动关麦、离房或结束使用时才释放采集。

当前豆包模式使用本地 Silero VAD v6 人声检测：独立 Worker 中运行单线程 WASM，开始讲话门槛为 0.5、续讲门槛为 0.35；已有约 500ms 起始缓冲和建连缓存，约 1.6 秒静音后结束云端会话。模型和运行时均从本站加载，不向检测服务上传音频、不依赖 Web Speech API。检测失败、超时或积压会停止识别并释放采集，不自动退回持续上传。800ms 静音断句不是已实现的保证，也不等于最终字幕延迟；安卓后台和精确计费仍需单独验收。

设备端 VAD 仍需要麦克风权限、音频采集和推理运行环境；操作系统暂停应用时，不能保证继续检测和自动恢复。迁移方案、开源参考与验收要求见 [跨平台语音与自动停止上传](docs/cross-platform-audio.md)。当前仓库克隆不会自动安装依赖、构建网页或安装本机常驻任务。

重新安装：构建成功后运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-local.ps1`。安装固定当前项目和 Node 路径；移动项目或 Node 后需重新安装。任务以当前用户的普通权限运行，登录触发，不需要保存账户密码；异常退出最多重试三次。卸载时在任务计划程序禁用、结束并删除 `HakiSub-Local`，再删除桌面快捷方式，不影响代码或 Key。

## 配置豆包 ASR 2.0

### 用量异常诊断（默认关闭）

本地模拟房间内「豆包配置」卡片下方提供语音用量：最近一次（或正在进行）的上传时长、本地服务启动以来累计上传时长、豆包返回的音频时长及 Request ID。页面每秒查询本机内存，不调用云端，不要求开启调试日志。关闭设置即停止轮询。停止识别、刷新网页保留统计，重启网关清零；更换 Key 不清零，累计值不属于某个账户。旧版本没有记录的用量不能补回。

这是上传量，不是账单、现金余额或剩余小时额度；静音也计入上传。服务端 `audio_info.duration` 按官方定义的毫秒换算显示，缺失时显示“尚未返回”。官方有独立的资源包状态与资金余额管理接口，目前尚未接入；语音 API Key 不等同于管理查询所需的 AK/SK。不得根据上传时长猜测真实余额。

停止已有开发服务，在 PowerShell 执行以下命令启动带统计的服务。启动本身不会调用豆包，只有手动开启豆包麦克风才会上传并可能产生费用：

```powershell
$env:HAKISUB_ASR_DEBUG = '1'
npm run dev
```

终端输出 `[ASR DEBUG]`：每个会话的 Request ID、开始/结束时间、经过秒数、音频包数、提交的 PCM 字节数和换算秒数、发送回调成功的字节数和秒数，以及最新 `audio_info.duration` 原始数值（未返回则为 null）。每 50 包输出一次进度，结束输出汇总。不记录 Key、音频或文字，不写日志文件。关闭服务后执行 `$env:HAKISUB_ASR_DEBUG = '0'` 再启动即可关闭；此开关读取启动进程环境，不从 `.env` 读取。

16kHz × 16-bit × 单声道对应每秒 32000 PCM 字节，每包 6400 字节即 0.2 秒。`submittedAudioSeconds` 是交给上游 WebSocket 的音频时长；`completedAudioSeconds` 是发送回调成功的时长，不等于服务端接收确认或计费时长。结束时尚未完成的发送可能导致两者不同。`serverDuration` 仅保留服务端字段原值，不累加、不推断计费单位。对照同一个 Request ID 的日志和控制台记录排查；旧会话没有日志则无法追溯。

房间中选择豆包并手动开麦后，会显示“本次开麦”计时，以及提交、发送完成、豆包返回的音频时长。开麦时间从麦克风实际进入监听状态算到关闭或报错，包含静音等待；后三项按自动断句产生的各个 Request ID 累加，同一连接的进度更新不会重复计入。“豆包返回”取响应里的 `audio_info.duration`，不等于账单时长，也可能暂时为空。关麦后数值冻结，下次手动开麦重置；切换模式、识别来源或离房即清除。数据只在当前页面内存中，不保存历史。对比额度变化时请同时记下测试起止时间、开麦时长、提交时长和返还时长，额度显示可能存在刷新延迟。

本地模拟已经验证：16k/44.1k/48k 输入一分钟均生成 300 包、1920000 PCM 字节，经网关到假上游仍为 60 秒。未发现时长翻倍；这不代表实际浏览器采集与云端扣量已经验收。当前二遍识别保持开启，不能凭名称认定会双倍扣量，也未为诊断更改识别参数。

### 填写密钥

1. 在火山引擎豆包语音控制台开通「豆包流式语音识别模型 2.0」小时版，确认 API Key 有 `volc.seedasr.sauc.duration` 的调用权限及可用额度。
2. 创建真实联网房间后，在房间内点击「豆包配置」，在豆包 API Key 密码框中粘贴 Key，点击保存。保存后立即对下一次识别生效，无需重启。页面只显示是否已配置，不回显已保存的 Key。
3. 点击「测试连接」。这只检查WebSocket握手，不发送音频，不能代替讲话验收。收起配置，保持“豆包 ASR 2.0”，手动开启麦克风并允许权限。

房间Key只保存在当前网关进程内存中，不回显给成员。匿名房主用原浏览器管理，已绑定房主登录同一UID可跨设备重填、更换或删除Key。退出房间不清除当前进程Key，后端重启必清除。

### 本地模拟与旧默认 Key 的兼容配置

旧本机独立模式的Key保存在根目录 `.env` 中，**是明文文件，不是加密保险箱**；不要分享此文件。密码输入只在保存时发给本机网关，不写入浏览器存储，操作后清空。可以在设置中更换或删除；识别期间须先停止麦克风。本段只适用于本地模拟的无房间会话；联网房间不使用该Key。旧本机设置接口继续仅供本机管理，尚无账户额度隔离。

也可以手动将 `.env.example` 复制为 `.env`（已有文件不要覆盖），编辑后重启服务：

   ```dotenv
   DOUBAO_API_KEY=在这里填写你的真实APIKey
   ```

不要使用 `VITE_` 前缀、不要将 Key 发进聊天或提交 Git。`.env` 已被忽略；`.env.example` 保持空值。如果启动进程已设置 `DOUBAO_API_KEY` 环境变量，它优先于文件，页面会显示只读；需移除该环境变量并重启后才能在页面管理。

麦克风音频经本地网关发送到豆包云端；这不是离线识别。临时文字在原位置更新，供应商确认 Final 后才启动既有渐隐计时。应用不保存音频文件或识别历史，也不记录密钥、音频、完整识别响应。

停止、切换来源、切换模式、离开房间、关闭或离开页面、断线会关闭采集和云端连接，丢弃未确认字幕，已确认字幕自然过期。切换到其他窗口或标签页不主动关麦；浏览器若实际暂停音频图，应用会尝试恢复，恢复失败时提示重新开启。手动停止属于取消，不等待最后一句补完；最后不足 200ms 的本地音频被丢弃。上传积压/音频传输中断会停止；单次云端会话最多 15 分钟。

豆包模式使用本地人声检测：手动开启麦克风后持续采集，Worker 将 16kHz PCM 按 512 样本（32ms）及 64 样本上下文送入 Silero v6，以每个 200ms 包中的最大人声概率判定起止。静音等待期间不建立云端连接、不上传音频。触发前的环形缓冲默认保留约 500ms（按 200ms 包取整，最多三个触发前的包），可在 `voiceActivityGate.ts` 配置；建连时继续缓存音频，连接就绪后按顺序逐步补发，再转入实时上传。持续安静约 1.6 秒后发送结束包，等待最后一句确认及旧连接实际关闭，下一次讲话才自动建新会话。手动关闭仍立即释放麦克风。模型加载和推理期间仅做有界缓存，检测失败不会静默退回持续上传。人声模型仍可能漏检或误检，也不能排除电视等其他人声；短暂停顿和起止缓冲仍会上传，不能保证精确按说话秒数计费。浏览器 ASR 模式不使用这套检测。

浏览器 ASR 和模拟字幕仍可在没有 Key 时使用。本地模拟模式只有「我」采集真实音频；真实联网房间为每位成员独立采集和识别，再共享字幕。

### 怎样验收豆包识别

1. 连续说一句较长的话：应逐步出现文字且不新增重复行。
2. 停顿后继续第二句：第一句确认后渐隐，第二句单独显示；文字长短仍遵循下方 3/6/10 秒规则。
3. 点击关闭麦克风后继续说话：不应新增文字，Chrome 麦克风占用应释放。在开发者工具 Network 中 `/api/asr` 连接关闭，不再发送音频帧。
4. 测试拒绝权限、断网、切换来源和离开房间：应停止并在适当位置提示，不能无限重连。切换窗口/标签页应继续保持麦克风，离开或关闭页面应停止。
5. 切回浏览器 ASR 和模拟模式检查原有流程。不要将模拟测试通过当作豆包真实调用验收。

自动检测的会话顺序、每次句首缓冲、模型故障及取消清理已通过本地模拟，真实模型另有 WASM 静音与公开语音样本检查。真实麦克风的短句、轻声、后台状态和豆包服务端断句仍需单独验收；模型升级后的效果不能由旧音量检测的结果代替。识别准确率、延迟和长时间稳定性不能由模拟结果保证。

## 保留的固定分屏

按成员 ID 和加入顺序固定位置，发言不改变顺序：

| 人数 | CSS Grid 布局 |
| --- | --- |
| 1 | 1 列 1 行 |
| 2 | 1 列 2 行，上下等高 |
| 3 | 2 列 2 行，首位成员占满第一行 |
| 4 | 2 列 2 行等分 |
| 5 | 2 列 3 行，首位成员占满第一行 |
| 6 | 2 列 3 行等分 |
| 7 | 2 列 4 行，首位成员占满第一行 |
| 8 | 2 列 4 行等分 |

每张卡片独立显示多句，旧句在上，新句在下。第一句从内容区域顶部开始，未溢出时按正常文档流向下排列，不滚动。仅当内容高度超出可视区域时，自动滚动到底部显示最新字幕；不提供手动翻阅。移除旧句后自然重排，内容不足一屏时恢复顶部对齐。内容增长、删除、卡片尺寸或字体变化时均重新判断是否溢出，房间高度固定为视口高度。

每位成员最新出现的一句话（含 Interim）使用标准字号的 100% 和 700 字重；其他句子使用标准字号的 88% 和 400 字重。新句出现时上一句立即切换为历史样式，新句消失后不会回退加粗旧句。

## 动态卡片布局实验

当前通过头像设置内的动态自适应／固定等分选项切换，默认动态并本机持久保存；原布局算法和固定Grid规则保留，debug=1可对比原调试控件。

动态模式读取每张卡片当前字幕流的实际高度（包括尚未过期的 Final 和 Interim），以 32px 高度分桶并限制需求权重。先预留约 80px 的最小空间（依据标题高度增加），再把剩余空间按需求分配；可用空间不足时取消额外分配并收紧卡片内边距与麦克风按钮，让姓名和状态优先可见。左右两列独立分配高度，成员不按活跃度排序，3/5/7 人的第一位继续横跨两列。

内容引起的尺寸调整每 600ms 最多一次，小于 12px 的变化忽略；均衡恢复不受该阈值阻挡。高度和顶部位置使用 300ms 过渡。视口大小或成员人数改变时重新计算，内容始终限制在房间可用区域内，保留卡片内部从顶部开始、溢出后跟随最新字幕的逻辑。

本次已用 Chromium 在 320×568、390×844、480×720 视口实测 1～8 人动态布局的卡片边界、无重叠和标题可见性，并验证 8 人内容扩张、历史/最新字号、溢出跟随、固定/动态切换和过期后均衡恢复。浏览器测试工具临时安装于 `/tmp`，未添加项目运行依赖。

对比建议：8 人房间运行“卡片内容溢出”，观察首位成员增高、同列其他成员收缩；运行“1 分钟压力测试”对比密集与稀疏阶段；待字幕过期后检查均衡恢复；期间切换固定/动态模式，字幕计时不会重置。

## 字幕生命周期

| 最终字数 | 完整显示 | 渐隐 | 总时长 |
| --- | --- | --- | --- |
| 1～15 | 3 秒 | 2 秒 | 5 秒 |
| 16～30 | 6 秒 | 2 秒 | 8 秒 |
| 31 及以上 | 10 秒 | 2 秒 | 12 秒 |

字数采用 Unicode 字符计数，排除标点和空白；中文逐字计数，混合文本中的字母、数字等也计入。每句 Final 保存独立的确认时间和显示时长。共享 50ms 时钟计算各自透明度及清理，不会因新句到来而重置旧句。后台页面恢复后按实际时间清理，不延长过期字幕。

`recognize(memberId, utteranceId, text, state)` 是当前识别事件入口。同一句的 Interim 和 Final 使用相同且稳定的 utteranceId；下一句使用新 ID。Interim 原位更新且不计时，Final 才开始生命周期，队列中重复 Final 不会重置时间。实际识别服务接入时需保证每人一句一个唯一 ID 并按顺序投递。关闭模拟麦克风会丢弃未确认的 Interim，已确认的 Final 继续自然过期。

## 手动测试

输入显示名称进入房间，在“模拟字幕”下拉框选择场景后点击“运行”。测试期间字幕照常消失，当前场景结束后可再次运行。普通场景使用第一位已开启模拟麦克风的成员；8 人场景和一分钟压力测试自动补齐成员并开启所有模拟麦克风。

1. **单人连续快速讲话**：700ms 间隔加入三句，确认三条共存、分别消失。
2. **8 人同时讲话**：8 人同时各发一句，900ms 后各追加一句，确认字幕互不干扰、位置不变。
3. **长句（超过 30 字）**：确认完整显示 10 秒，之后渐隐 2 秒。
4. **渐隐时加入新句**：短句出现 4 秒后追加新句，此时前句约半透明，新句仍完整显示。
5. **卡片内容溢出**：每 100ms 添加一句，共 20 句。切换 1～8 人，确认最新句在底部、旧句裁切，滚轮、触屏及键盘无法翻阅旧内容，页面不被撑高。
6. **实时识别到确认**：每 250ms 增长一次同一条字幕，正文不附加状态文字；确认后按最终字数开始计时，随后追加新句。

7. **8 人对话 · 1 分钟压力测试**：自动补齐 8 人，以周末出行讨论为主题，共生成 81 句。每 10 秒交替密集发言（24 句）和稀疏发言（3 句），覆盖短、中、长三档字幕，以及多人重叠发言。每句先经历四次 Interim 更新，再确认 Final。底部显示秒数进度及当前节奏；60 秒结束发言后，剩余字幕按原生命周期自然消失，最长再等待 12 秒。期间固定演示人数为 8 人，麦克风仍可独立切换，离房会取消后续事件。脚本固定，便于重复对比性能与布局。

建议浏览器以 320px、390px、480px 宽度及不同高度检查所有人数布局。自动测试覆盖字数边界、渐隐边界、新旧句独立计时、Interim 到 Final、重复确认、成员隔离、静音、人数变化、六种基础模拟、一分钟压力测试及离房/卸载清理。

## 单设备浏览器 ASR（保留功能）

本地模拟房间上方“输入”可切换“模拟字幕”和“真实麦克风”。真实模式点击“开启麦克风”才请求权限；默认保持模拟模式，不自动采集。识别语言为普通话 `zh-CN`，只写入“我”的卡片，其他成员显示“未接入设备”。浏览器通过 Web Speech API 自行采集麦克风并执行识别，没有额外创建 MediaRecorder 或重复的 getUserMedia 音轨。

每次识别会话与结果索引组合成稳定句子 ID，Interim 原位更新，`isFinal` 确认后交给原有 3/6/10 秒显示和 2 秒渐隐规则。浏览器决定断句，不能保证按每个中文标点分句。重复 Final 被过滤，识别器撤回的 Interim 会移除。停止时丢弃未确认字幕，保留已确认字幕自然过期。

关闭麦克风、离房、切回模拟、页面隐藏或离开页面时会 abort 识别并清除重连任务；再次回到页面需要手动开启。切换输入模式清空当前字幕并取消模拟调度，避免混入两种来源。浏览器正常结束会话或无语音时最多连续重试两次，收到结果后重置重试次数；授权、网络、设备等错误立即停止并提示，不无限重试。重连期间可能漏掉语音，不做音频缓存或补录。

### 方案、兼容性、延迟与费用

- 使用 `SpeechRecognition` / `webkitSpeechRecognition`，启用 `continuous` 和 `interimResults`。优先在桌面 Chrome 验证；Safari 有实现但依赖系统语音配置。其他浏览器、手机和内嵌 WebView 以能力检测和实际服务可用性为准，不把接口存在视为识别成功。
- 使用 HTTPS 或本机 localhost。Codespaces 应从端口面板打开独立的 HTTPS 浏览器标签页；HTTP 局域网 IP 不适合手机麦克风测试。内嵌预览可能受权限策略限制。
- 临时结果 0.5～2 秒、停顿后 1～3 秒确认仅为工程验证目标，尚未实测，也不是浏览器服务 SLA；网络、设备、句长和服务断句会改变延迟。
- 此实现无需 API 密钥，没有配置付费 ASR 账户或按量计费接口；网络流量可能产生费用。浏览器识别服务的可用性和限制由浏览器厂商决定。
- 浏览器可能把音频发送到其在线识别服务，例如 Chrome 的服务端识别。当前网络无法访问服务时会报错，不能保证离线或所有地区可用。应用自身不录音、不保存或上传音频到应用服务器；浏览器服务的数据处理不由本应用控制。页面内存字幕过期不等于远端服务的数据删除承诺。
- 现在也可选择上文的豆包模式，其麦克风采集和连接由独立模块负责，密钥仅由本地网关读取。

参考：[Chrome Web Speech API](https://developer.chrome.com/blog/voice-driven-web-apps-introduction-to-the-web-speech-api?hl=en)、[Safari 语音识别](https://webkit.org/blog/11648/new-webkit-features-in-safari-14-1/)、[MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。

### 真实设备验收

1. `npm run dev`，在独立浏览器标签页打开 HTTPS 转发地址（本机可 localhost）。创建房间并选择“真实麦克风”。
2. 点击“开启麦克风”，允许权限，确认状态从请求授权变为“麦克风已开启 · 普通话”。
3. 连续说几句普通话并在句间停顿，确认临时文字在同一句更新，Final 后开始独立渐隐，下一句另起一条并加粗。
4. 关闭麦克风后继续讲话，确认没有新字幕，浏览器停止采集；已确认字幕继续自然过期。
5. 分别测试拒绝授权、浏览器禁用麦克风、断网、切换输入、切后台及离房。恢复权限或网络后点击开启重试。
6. 切回模拟模式，再运行一分钟压力测试，对比卡片行为。

自动测试使用假识别引擎，可验证事件与状态逻辑，不能证明实际硬件、浏览器服务、识别准确率或延迟。当前开发环境尚未完成真实麦克风听写验收。

## 当前模拟范围

本地模拟模式仍接受任意 6 位数字码，成员和字幕仅在本页；真实联网模式由服务端创建及验证房间，最多 8 人同步成员和字幕。网关最多允许 8 路成员 ASR，每人一路；实际豆包并发额度和真实多人效果尚未验收。服务仍绑定本机地址且限制本机 Origin，尚未完成公网部署。没有外接麦克风路由、串音过滤或降噪；`/glasses` 仍为静态概念预览。

## 浏览器 ASR 的 800ms 静音断句限制

当前使用浏览器 Web Speech API，由浏览器自行控制断句。接口没有静音阈值配置；`continuous` 不等于自定义断句，`speechend` 不是可配置为 800ms 的 VAD。当前没有独立 VAD，也没有用“800ms 未收到文字”作为静音判断。参见 [Web Speech API 接口规范](https://webaudio.github.io/web-speech-api/#speechreco-section)。

正文和成员状态栏已移除“识别中／正在识别”文字，保留麦克风开关、未接入设备和权限错误信息；原有字体层级、布局、滚动与字幕生命周期未改动。

浏览器模式的原方案及限制见 [音频断句方案](docs/audio-segmentation.md)。豆包模式启用云端二遍识别以获取确定分句，采用服务默认判停；不等同于本地 VAD 或精确 800ms 的端到端字幕延迟承诺。0.3/0.6/0.9 秒真实音频停顿、多次犹豫、长对话和连续 10 分钟场景均待真实验收。
